## 3. 结构性决策记录（供勘误）

1. **图形态**：根（里程碑）→ 5 字母域包（A–E）→ 编号域包（A1…D6；E 无编号层）→ BOM 条目节点。动因：MCP 面保守默认 fan-out=12、单提案节点数≤50——44/61 条不能平铺，域包分层同时贴合 BOM 自己的功能域划分。
2. **BOM 编号即节点 display ID**：slot_key 保留编号（`A1-1`→`a1.1`、`E4`→`e4`），human_code 另发 `MST-WI-00701..00805`（清单序），映射在 `data/bom-manifest-20260909.json` + 扁平 work_items.description 双留。
3. **原子性字段的占位性质**：work_item 节点必填 repo/baseline/workspace/capability。骨架期统一 pin `peixun-backend` + `doc/` + 当前 main SHA + 域级 capability——**这些是占位**，S2B 逐条详设后经重规划改 pin（尤其 D2-1 H5 移动端的仓属未知）。预算=BOM 人日原值。
4. **二三期占位不封板**：m23 图保持 draft——封板即冻结结构，占位转正（重规划）是各期启动时的详设先行动作。
5. **D 域一期 6 条**（含 D4-1 操作与登录日志）：域内无可推导边，全部依赖为跨域候选（见 §2）。
6. **「域」口径**：按 brief 列出的八组 {A1}{A2}{A3}{A5}{B}{C}{D}{E}——字母级 B/C/D/E 内允许建边（如 B5→B8、C1 内部），编号级 A1/A2/A3/A5 只在组内建边。
